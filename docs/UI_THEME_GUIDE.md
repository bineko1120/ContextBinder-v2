# ContextBinder v2 UIテーマ設計・適用方針

この文書は、Visual Studio Designerで作成した共通レイアウトへ、後から複数の完成デザインを安全に適用するための要件と役割分担を定めます。

このテーマ方針は、`MainFormDesignDraft`の配置作業が終わった後も継続して使用します。

---

# 1. 結論

ContextBinder v2は、フォームをテーマごとに複製せず、次の構成を基本とします。

```text
共通のMainForm
＋
洗練されたデザインテーマ
＋
猫あふれる可愛いデザインテーマ
```

同じ画面、同じコントロールの`Name`、同じPresenter、同じ機能処理を使い、見た目だけをテーマとして切り替えます。

Visual Studio Designerの標準的な見た目は完成デザインではありません。Designerは主に、画面構造、配置、親子関係、操作導線を作るためのワイヤーフレーム作成環境として使います。

---

# 2. 状態

## 確定

- MainFormはテーマごとに複製しない
- 1つのMainFormへ複数テーマを適用する
- 最低限、次の2テーマを用意する
  - 洗練されたデザイン
  - 猫あふれる可愛いデザイン
- Designerでは共通の骨格と操作導線を作る
- 完成デザインは、Designer画面のスクリーンショット等を基に少佐とChatGPTで設計する
- Codexは確定したテーマ仕様を実装する
- テーマ変更によって機能、保存データ、`Name`契約を変えない
- `.Designer.cs`へテーマ処理を直接書かない

## 暫定

- テーマ値はJSON等の外部テーマファイルへ集約する
- テーマ確認専用画面`UiThemePreviewForm`を用意する
- 実行中にテーマファイルを再読み込みできるようにする
- 標準WinForms部品で不足する箇所だけ、テーマ対応カスタムコントロールを導入する

## 未確定

- 各テーマの正確な配色
- フォント名とサイズ
- 角丸の大きさ
- アイコンと猫装飾の具体的な絵柄
- ライトテーマ、ダークテーマの有無
- アニメーションの有無
- テーマ名の正式な日本語名と内部名

---

# 3. 役割分担

## 少佐が決めるもの

- 画面内の機能配置
- 操作導線
- 見た目の好み
- テーマごとの雰囲気
- 配色、装飾、アイコンの採用案
- 画面を見た上での文字切れ、余白、違和感の判定
- 最終的な採用テーマ

## ChatGPTが行うもの

- Designer完成画面の視覚レビュー
- 洗練テーマと猫テーマのデザイン案作成
- 配色、文字階層、余白、状態表現の仕様化
- テーマ間で共通にする部分と変える部分の整理
- Codex向け実装指示の作成
- 実装後のスクリーンショットレビュー
- 受け入れ条件との照合

## Codexが行うもの

- テーマ定義モデル
- テーマ読込処理
- テーマ適用処理
- テーマ切替設定
- プレビュー画面
- 必要なカスタムコントロール
- テーマ別リソースの読込
- 高DPI、日本語文字切れ、ホバー、押下、無効状態の検証
- Designerの配置を壊さない実装

---

# 4. Designerを正本とする範囲

Designerは、主に次を決める正本です。

- コントロールの親子関係
- 大きな領域の構造
- 操作対象同士の位置関係
- `Name`
- `Dock`
- `Anchor`
- 基準となる`Location`
- 基準となる`Size`
- `TabIndex`
- 初心者向け操作とコンパクト操作の配置

テーマ処理は、原則として次を勝手に変更しません。

- `Name`
- 親コンテナ
- 子コントロールの順序
- `Location`
- `Size`
- `Dock`
- `Anchor`
- `TabIndex`

ただし、少佐がプレビューを見ながらテーマごとの軽微な調整を許可した場合は、明示的に許可された範囲だけ変更できます。

---

# 5. テーマで変更するもの

## 原則として安全に変更できるもの

- `BackColor`：背景色
- `ForeColor`：文字色
- `Font`：フォント
- `Image`：ボタンやPictureBoxの画像
- `BackgroundImage`：背景画像
- アイコン
- 枠線色
- 枠線の太さ
- 角丸
- ホバー時の色
- 押下時の色
- 選択中の色
- 無効状態の色
- フォーカス表示
- テーマ別の猫装飾画像
- テーマ別の空状態画像

## 配置へ影響するため条件付きで変更するもの

- フォントサイズ
- `AutoSize`
- `Padding`
- `Margin`
- コントロールの高さ
- アイコンサイズ
- テキストと画像の間隔
- 装飾Panelの`Visible`

これらはプレビューと実画面で確認し、文字切れや再配置が起きないことを検証します。

## 原則としてテーマ側から変更しないもの

- 大きなPanelの`Dock`
- 大きなPanelの`Anchor`
- 大きなPanelの`Margin`
- 大きなPanelの`Padding`
- `SplitContainer`の構造
- コントロールの親子関係
- DataGridView列の意味と`Name`

# 6. 2つのテーマの方向性

## 6.1 洗練されたデザイン

目的：情報を見やすく整理し、長時間使っても疲れにくい、機能的で完成度の高いデザインにします。

方向性の例：

- 低彩度の落ち着いた配色
- 明確な情報階層
- 細く控えめな境界線
- 小さめまたは中程度の角丸
- 統一された線画アイコン
- 選択、ホバー、フォーカスを明確に区別
- 装飾は控えめ
- 猫要素はロゴや種類アイコン等へ限定してもよい
- 情報密度と視認性の両立

## 6.2 猫あふれる可愛いデザイン

目的：操作性を損なわず、猫らしさと楽しさを画面全体へ反映します。

方向性の例：

- 柔らかい背景色
- 丸みのあるボタンと領域
- 肉球、猫耳、しっぽ等の装飾
- 猫がファイルやフォルダーを持つアイコン
- 空の一覧や検索結果なし状態に猫イラスト
- ステータス表示へ小さな猫アイコン
- 猫用段ボール等を使った「登録のごみ箱」表現
- ホバーや選択時に小さな猫らしい反応
- 可愛さだけで文字や操作が読みにくくならないこと

# 7. 猫装飾の配置ルール

猫テーマだけで使う装飾候補：

```text
catHeaderDecorationPictureBox
catGroupDecorationPictureBox
catEmptyStatePictureBox
catFooterDecorationPictureBox
catPawOverlayPictureBox
catDecorationPanel
```

## 配置を崩さない方法

- 装飾を通常UIの上へ重ねる
- 装飾専用の固定領域をあらかじめ確保する
- 洗練テーマでも装飾用領域自体は残し、画像だけを空にする
- FlowLayoutPanelやTableLayoutPanel内の装飾Panelを単純に非表示にして、他の部品が詰まらないようにする
- 装飾は操作を遮らないようにする

装飾用コントロールの参考設定：

```text
TabStop = false
Enabled = false
BackColor = Transparent
```

# 8. テーマファイル

テーマ値をC#コードへ大量に直書きせず、外部ファイルへ集約する案を優先します。

参考構成：

```text
Themes/
├─ Refined.theme.json
└─ CatCute.theme.json
```

テーマファイルへ含める候補：

- フォント名
- 本文サイズ
- 見出しサイズ
- ウィンドウ背景色
- Surface色
- 標準文字色
- 補助文字色
- アクセント色
- 警告色
- エラー色
- 枠線色
- ボタンの角丸
- ボタン内Padding
- セクション内Padding
- コントロール間隔
- アイコンサイズ
- テーマ別画像の参照先

少佐が値を書き換えた後、保存して再読み込みし、すぐ画面へ反映できる構成を目標とします。

# 9. テーマプレビュー画面

本番画面だけで調整すると確認に時間がかかるため、テーマ専用プレビュー画面を用意する案を採用します。

仮称：

```text
UiThemePreviewForm
```

表示するもの：

- 通常ボタン
- ホバー状態
- 押下状態
- 無効状態
- フォーカス状態
- Label
- 見出しLabel
- 補助説明
- 警告
- エラー
- TextBox
- ComboBox
- CheckBox
- ListBox
- DataGridView
- MenuStrip
- ToolStrip
- 種類アイコン
- 空状態
- 検索結果なし
- 読み込み中
- 未保存状態
- 猫装飾

欲しい操作：

- テーマ選択
- テーマ再読み込み
- 100% / 125% / 150%相当の表示確認
- 長い日本語文言の確認
- 通常、ホバー、押下、無効、フォーカス状態の確認

# 10. カスタムコントロール

標準WinForms部品だけで十分な箇所は、そのまま使用します。

角丸、自由な枠線、統一されたホバー表示等が必要な箇所だけ、次のようなテーマ対応部品を検討します。

```text
ThemedButton
ThemedIconButton
ThemedPanel
ThemedGroupBox
ThemedTextBox
ThemedDataGridView
ThemedToolStripRenderer
```

カスタムコントロールを導入する場合も、Designerで設定した`Name`、位置、サイズ、操作目的を維持します。

---

# 11. 実装ファイルの責務

参考構成：

```text
MainFormDesignDraft.Designer.cs
    Designerが管理する配置。手書きのテーマ処理を入れない

MainFormDesignDraft.cs
    初期化とテーマ適用の入口

Themes/Refined.theme.json
    洗練テーマの値

Themes/CatCute.theme.json
    猫テーマの値

UiTheme.cs
    テーマ識別子

UiThemeDefinition.cs
    テーマ定義モデル

UiThemeService.cs
    コントロールへのテーマ適用

UiThemePreviewForm.cs
    テーマ確認画面
```

`.Designer.cs`はVisual Studioが再生成するため、手書きのテーマ処理や複雑なロジックを書きません。

# 12. 作業手順

1. 少佐がDesignerで共通MainFormの骨格と操作導線を作る
2. Codexが既存機能をPresenter / Service経由で接続する
3. 少佐が完成画面のスクリーンショットをChatGPTへ共有する
4. 少佐とChatGPTで洗練テーマと猫テーマを設計する
5. 配色、フォント、余白、状態表現、装飾、アイコンを仕様化する
6. Codexがテーマシステムと必要なカスタムコントロールを実装する
7. テーマプレビュー画面で全状態を確認する
8. 少佐がテーマファイルを調整しながら見た目を詰める
9. MainFormで日本語文字切れ、高DPI、狭い画面を確認する
10. 2テーマの受け入れ条件を満たした後に完成扱いとする

---

# 13. 受け入れ条件

## 共通

- 同じMainFormで2テーマを切り替えられる
- テーマを切り替えても機能と保存データが変わらない
- コントロールの`Name`が変わらない
- テーマごとにフォームやPresenterを複製しない
- `.Designer.cs`へテーマ処理を直書きしない
- テーマ変更後も主要操作が実行できる
- テーマ切替後にレイアウトが意図せず崩れない

## 表示

- 日本語のボタン文字と説明文が切れない
- 100%、125%、150%の表示倍率で主要画面を確認する
- 長いタイトル、長いパス、長いURLで確認する
- 通常、ホバー、押下、無効、選択、フォーカス状態を区別できる
- 文字と背景のコントラストが不足しない
- アイコンだけの操作にToolTipとAccessibleNameがある

## 洗練テーマ

- 情報階層が明確
- 装飾が操作を邪魔しない
- 長時間利用で視認性を損なわない
- 標準WinFormsの未調整な見た目が主要部分に残らない

## 猫テーマ

- 猫要素が十分に感じられる
- 可愛さのために文字、状態、操作対象が分かりにくくならない
- 猫装飾がクリックやスクロールを妨げない
- 猫装飾の表示切替で周囲の配置が意図せず動かない

---

# 14. Codexへ実装を依頼するときの基準

このテーマ実装を依頼する際は、次を明示します。

```text
Designerで設定された配置とName契約を正本としてください。

テーマ適用処理から、明示的な許可なく次を変更しないでください。
- Name
- 親コンテナ
- 子コントロールの順序
- Location
- Size
- Dock
- Anchor
- TabIndex

テーマで変更してよいもの：
- BackColor
- ForeColor
- Font
- Image
- BackgroundImage
- アイコン
- 枠線
- 角丸
- ホバー、押下、選択、無効、フォーカス状態
- 猫装飾用画像
- 個別に許可されたPadding、Margin、高さ

Visibleの変更でレイアウトが再配置される場合は、コンテナ全体を非表示にせず、画像や描画内容だけを切り替えてください。

テーマごとにフォーム、Presenter、機能処理を複製しないでください。
```
